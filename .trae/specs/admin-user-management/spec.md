# 管理员后台管理 - 用户管理功能规格

## 一、功能概述

**问题/机会**：当前系统缺乏管理员功能，无法查看和管理注册用户信息。随着用户数量增长，需要一个后台管理界面来监控用户情况。

**解决方案**：为管理员创建一个后台管理页面，提供用户管理功能。初期版本仅支持查看用户列表，后续可扩展编辑、删除等功能。

## 二、变更内容

### 2.1 后端 API 变更

**新增 API 端点：**

1. `GET /api/admin/users` - 获取所有用户列表（管理员专用）
2. `GET /api/admin/users/{user_id}` - 获取指定用户详情
3. `GET /api/admin/stats` - 获取用户统计信息

**新增认证机制：**

- 管理员角色标识（`is_admin` 字段）
- 管理员权限验证中间件

### 2.2 前端变更

**新增管理页面：**

- 独立的 `/admin` 路径
- 用户管理面板
  - 用户列表展示
  - 用户搜索和筛选
  - 用户详情查看
  - 统计信息展示

**新增组件：**

- 管理员登录页面
- 用户管理主页面
- 用户详情卡片
- 统计信息面板

  - sort_by: 排序字段（created_at, last_login）
  - sort_order: 排序方向（asc, desc）

Response:

  "users": [

      "user_id": "user_xxx",

### 3.4 权限控制设计

**管理员标识：**
- 数据库 `users` 表增加 `is_admin` 字段（Boolean，默认 false）
- `user_id='admin'` 初始管理员账户

**权限验证流程：**

```
1. 用户访问 /api/admin/* 接口
2. 验证 JWT Token 有效性
3. 检查用户 `is_admin` 字段
4. 通过则返回数据，拒绝则返回 403
```

**非管理员用户访问限制：**
- 尝试访问 `/admin/*` 路径 → 重定向到首页
- 尝试访问 `/api/admin/*` 接口 → 返回 403 错误

### 3.5 管理员登录

**方案：使用专用管理员账户**

- 初始管理员：`admin@mystock.local` / 密码：`admin123`（仅本地使用）
- 管理员密码应通过环境变量或配置文件设置
- 不提供公开注册管理员的功能

**管理员登录 API：**

```
POST /api/admin/login
Body:
{
  "email": "admin@mystock.local",
  "password": "admin123"
}
Response:
{
  "token": "admin_jwt_token",
  "user": {
    "user_id": "admin",
    "email": "admin@mystock.local",
    "is_admin": true
  }
}
```

## 四、业务规则

1. **管理员唯一性**：系统只有一个管理员账户
2. **权限隔离**：普通用户无法访问管理后台
3. **数据可见性**：管理员只能查看用户数据，不能修改
4. **分页限制**：用户列表每页最多显示 100 条
5. **搜索功能**：支持按邮箱、昵称搜索
6. **排序功能**：支持按注册时间、最后登录时间排序

## 六、验收标准

### 6.1 功能验收

- ✅ 管理员可以使用专用账户登录
- ✅ 非管理员用户无法访问管理后台
- ✅ 管理员可以查看所有用户列表
- ✅ 用户列表支持分页显示
- ✅ 用户列表支持搜索功能
- ✅ 用户列表支持排序功能
- ✅ 管理员可以查看单个用户详情
- ✅ 管理员可以查看统计信息

### 6.2 安全验收

- ✅ 管理接口需要有效 Token
- ✅ 非管理员用户访问管理接口返回 403
- ✅ 管理页面需要管理员权限
- ✅ 普通用户访问管理页面被拒绝

### 6.3 性能验收

- ✅ 用户列表加载时间 < 1s
- ✅ 统计信息加载时间 < 500ms
- ✅ 用户详情加载时间 < 500ms

## 七、兼容性考虑

**向后兼容**：
- 现有用户认证系统不受影响
- 现有用户数据不受影响
- 非管理员用户使用体验不变

**数据库迁移**：
- 仅添加新字段，不修改现有表结构
- 提供回滚脚本
